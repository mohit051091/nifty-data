# Expiry calendar and NSE evidence

`expiries-monthly.csv` and `expiries-weekly.csv` are generated by `python -m backfill.build_calendar`. Each row has
`status` = `derived` or `verified`, a `basis` (the rule or holiday shift that produced it) and the `bhavcopy_url`
whose file would verify it. Nothing is marked verified by inference. `verify_expiries.py` flips a date only when the
bhavcopy for that session lists NIFTY option contracts expiring on it that traded that day, and for a monthly date
only when the index future also expires there. A file that contradicts the calendar aborts the run without writing.

## Rules used to derive dates

- Weekly: Thursday for nominal dates up to 28 Aug 2025, Tuesday from 2 Sep 2025 (NSE moved NIFTY expiries to Tuesday
  from 1 Sep 2025).
- Monthly: the last weekly date of the calendar month by actual date (last Thursday, then last Tuesday). April 2025 is
  30 Apr, not the NSE series date 24 Apr, because that is what Dhan's MONTH flag serves.
- Holidays: a nominal day that is not a regular trading session moves to the previous regular session.
  `sessions.csv` is the Bank Nifty repository's session list (NSE index history). It is the same exchange calendar and
  matches the 1,241 daily NIFTY candles Dhan returns for the window exactly.
- Not regular sessions, so never an expiry day: 24 Oct 2022, 12 Nov 2023, 2 Mar 2024, 18 May 2024, 1 Nov 2024 and
  21 Oct 2025 (Muhurat and Saturday special sessions). Only 21 Oct 2025 falls on a nominal expiry day, so that expiry
  is derived as Monday 20 Oct 2025. Check it first when bhavcopies arrive.
- 24 Nov 2026 is outside the window and so absent from `sessions.csv`. Dhan has no NIFTY candles for it, so the Nov 2026
  expiry is derived as Monday 23 Nov 2026 (the Bank Nifty repository's NSE-verified monthly expiry is also 23 Nov).

## Files NSE must supply

`bhavcopies-needed.csv` lists the F&O bhavcopy of every weekly expiry date (monthly dates included): 263 files. The same
files serve `verify_expiries.py` and `verify_mapping.py` (rollover-day opens). Save them under their original names in
one directory outside the checkout, then:

```sh
python -m backfill.verify_expiries --cache-dir /path/to/nse-cache --list-missing   # what is still needed
python -m backfill.verify_expiries --cache-dir /path/to/nse-cache                  # upgrade derived to verified
```

Until then use `--accept-derived-calendar`. Rows exported under it are recorded as `calendar_verified=false` in the
manifest.

## Dhan-only calendar check

`python -m backfill.verify_dhan_codes --expiry-type <type> --repo . --expiry-days --output ...` requests the ATM
straddle on every calendar date and checks that code 1 has decayed to almost no time value at the close and that a
fresh contract opens next session. It is evidence, not verification: dates stay `derived`. Results are in
`coverage/dhan-expiry-day-check-monthly.csv` (60 of 61 pass; the last needs a session after the window) and
`coverage/dhan-expiry-day-check-weekly.csv` (199 of 201 pass; 2024-09-12 and 2025-05-08 fail on thresholds only, with a
stale last price in the final candle while the call open interest collapses through the day, as on a real expiry).

## Relative expiry codes

Dhan `rollingoption` takes `expiryFlag` (`MONTH` or `WEEK`) and a relative `expiryCode`. For both flags code 1 is the
nearest expiry on or after the session date, so a contract is code 1 on its own expiry day, and code 2 is the next
expiry of that flag. On the day after an expiry the codes shift. Hence a contract with previous expiry P is fetched as
code 1 for sessions after P up to its expiry and as code 2 on P. `verify_dhan_codes.py` gathers the Dhan-only evidence
for this; `verify_mapping.py` is the NSE open-price check to use once bhavcopies exist.
